# 需求确认

## 要确认的四件事

| 项 | 取值示例 | 影响 |
|---|---|---|
| 对象类型 | 落地页 / 后台表格 / 表单流 / 组件库 | 决定优先检查的维度 |
| 阶段 | 设计稿评审 / 编码中 / 上线前体检 | 决定建议的抽象层级 |
| 关注点 | 布局、排版、色彩、响应式、无障碍、交互反馈、性能 | 决定路由到哪些知识叶子 |
| 严重度阈值 | 只报阻断项 / 全量清单 | 决定输出条数与排序 |

## 判定规则

- 关注点缺省＝全维度体检（按 [评审清单](../../../knowledge/评审清单/评审清单.md) 走一遍）。
- 设计稿阶段只给结构与规格建议，不臆断实现细节。
- 上线前阶段必须实测：对比度、键盘可达、断点行为、渲染预算。
