# 流程（Process）

本目录存放 web-design-expert 的执行流程细则，每个步骤独立成文件夹。

## 单一路径（专家指导）

```
[初始化/](初始化/初始化.md) → [需求确认/](需求确认/需求确认.md) → [领域路由/](领域路由/领域路由.md) →
[证据采集/](证据采集/证据采集.md) → [专家诊断/](专家诊断/专家诊断.md) → [改进清单/](改进清单/改进清单.md) →
[复审确认/](复审确认/复审确认.md) → [收尾沉淀/](收尾沉淀/收尾沉淀.md) → 完成
```

## 步骤列表

| 步骤 | 路径 | 说明 |
|---|---|---|
| 初始化 | [初始化/](初始化/初始化.md) | 确认调用方、目标产物与评审口径 |
| 需求确认 | [需求确认/](需求确认/需求确认.md) | 明确评审对象、平台、关注点与严重度阈值 |
| 领域路由 | [领域路由/](领域路由/领域路由.md) | 把关注点映射到知识叶子（见 knowledge/） |
| 证据采集 | [证据采集/](证据采集/证据采集.md) | 读代码/样式/截图/实测数据，缺证即声明 |
| 专家诊断 | [专家诊断/](专家诊断/专家诊断.md) | 逐条给出可执行判断与依据 |
| 改进清单 | [改进清单/](改进清单/改进清单.md) | 输出分级、可验收的改进项 |
| 复审确认 | [复审确认/](复审确认/复审确认.md) | 修复后复测，判定通过/回归 |
| 收尾沉淀 | [收尾沉淀/](收尾沉淀/收尾沉淀.md) | 沉淀新经验、释放 tmp、返回调用方 |

## 调用形态

被 SMS 主流程或编码技能（frontend-dev / ui-design / web-design-guidelines）在设计与评审阶段调用：
输入＝页面/组件/样式片段＋关注点；输出＝专家判断＋分级改进清单（模板见 [asset/评审报告模板.md](../../asset/评审报告模板.md)）。

约束兜底见 [resistance/](../../resistance/resistance.md)。
