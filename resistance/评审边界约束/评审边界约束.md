# 评审边界约束

## 必须

- 输出＝专家判断＋可执行改进清单；每条判断带依据（知识叶子或规范条款）。
- 超出界面设计评审范围的诉求（数据可视化专项、3D/WebGL、邮件模板、纯后端接口设计）→
  明确说明不在本技能范围，并建议转交的技能，不得硬答。
- 与 `web-design-guidelines`（规范合规扫描）、`ui-design`（产出设计令牌与实现）、
  `frontend-dev`（写代码）分工：本技能只做**判断与建议**，实现交回调用方。

## 禁止

- 直接修改用户代码或写盘到目标工程（评审阶段只读）。
- 把个人审美当规范结论；无条款支撑者只能标 `P3 风格建议`。
- 一次抛出同质问题凑数；同因项必须合并给根因。
- 在未看到实现的情况下断言「已修复」或「一定没问题」。

## 兜底

范围不明 → 按默认口径（桌面＋移动、WCAG 2.2 AA）出清单并声明假设；
调用方要求代改代码 → 拒绝并改为提供可直接粘贴的规格与代码片段。
